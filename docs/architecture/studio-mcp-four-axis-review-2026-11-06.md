## 修复与验证

保存按当前项目和前进版本安装，同版本流程同步仅使旧读取失效；较新草稿和较新后台版本保持。六种异步交错由独立审阅者复现通过。资产页明确选择项目/计划版本或工作区共用库，读写既有录入与审批记录；删除绑定被确认的副本，保留原文件。

采纳先验证真实改善，再把计划 CAS、用户决定、任务结果和新报告资源原子提交到同一项目记录。经验和报告是可恢复投影；保存失败不产生部分采纳，投影失败不丢失耐久决定。原报告资源保存不可变副本。

取消保留流式日志引用并快照到任务目录，后续执行不覆盖旧证据。启动只结算丢失的运行状态，保留已完成任务和真实批准，不推断权限或启动生产。成功/准备任务尚有依赖或审阅阻塞时，卡片明确结算为阻塞。

工具仍由 `ToolRegistry` 统一声明 schema、权限和处理器。MCP 只通过 Studio 同进程本机入口，校验 socket peer、Host、Origin 与 Bearer；模型确认参数不能兑换生产、审阅或采纳权限。验收客户端模型地址拒绝所有 query、userinfo 和 fragment，凭据仅进入子进程环境并从证据清理。

新增守卫已进入既有变异脚本。MCP 31 项和 FE21 18 项全部捕获；受接口形态调整影响的四个既有前端变异另行更新验证。所有源码按字节恢复，token、locale/theme、端点、词典、产品名和真实确认来源守卫保持。
