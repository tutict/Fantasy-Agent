# Godot 试玩反馈进化

入口在灵构工坊的「质量 → 试玩反馈进化」。更新代码后重启 Studio，使用构建后的前端。

## 使用

1. 在策划工作台确认一个 Godot 计划并交接到流程控制台。
2. 打开质量步骤的「试玩反馈进化」，设置候选数和总时间预算。
3. 点击「预览实验」，审阅将生成的独立灰盒、数值范围、Godot 操作和记录位置。
4. 明确确认后，基线与候选依次执行并试玩。默认最多三个候选，基线另算；默认总预算 600 秒，导入与试玩进程受剩余预算约束。可随时取消。
5. 查看每轮指标、参数差异、失败原因和工程位置。先人工试玩，再点击「采用最佳候选」，将修改写入当前计划并保存经验。
6. 后续任务可点击「读取经验建议 → 应用经验建议」；有限实验也可以先尝试相关的已采用经验。建议会按当前参数比例重新计算并校验范围。

采用经验不会自动启动下一次生产；执行仍通过原有确认流程。执行区的额外手动敌人调参仍按既有规则优先于 bundle，采用后请核对这些控件。

## 首版范围

实验只运行确定性 Godot 灰盒，不运行 Blender／ComfyUI，不修改生成器源码、核心动作、胜负规则或审批清单。内置候选主要针对计时失败和敌人追击压力；脚本、输入、路线和机制缺陷会指出人工返工方向。

可变字段为 `numeric.player_move_speed`、`numeric.pressure_clock_seconds` 和 `numeric.enemy_pressure` 中的数量、移动速度、侦测半径倍率。候选必须通过严格模型和当前 Spec 的调参范围。

改进由完整真实样本证明：重新计算汇总，检查胜利路径、动作交付、实际移动和已有机制作用，拒绝缺失采样、退化与伪造摘要。没有改善就保留原计划。机器人能检查循环可达性，乐趣与目标时长仍需要人工试玩。

## 记录与恢复

- 实验：`generated/evolution/experiments/<experiment_id>.json`。
- 采用后的经验：`generated/evolution/experiences.json`。
- 候选工程：`generated/godot/sessions/<experiment_id>-<iteration>/<project>/`。

决策记录使用原子替换，经验索引在工作区锁内更新。缺失记录与损坏记录区分报告。刷新只读取进度，Studio 重启后未完成实验显示中断，不自动重放。读取故障不会把已知运行中的任务显示为完成，取消入口仍可用。

库内实现位于 `fantasy_agent/evolution/`，六个本机 REST 接口由现有 Studio 提供。现阶段的验证包括模拟引擎、真实 ASGI、前端交互、跨端覆盖和变异检查；真实 Godot 的改善幅度需在用户确认实验后观察。
